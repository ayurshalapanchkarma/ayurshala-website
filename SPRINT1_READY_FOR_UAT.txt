SAFETY & EDGE CASES
================================================================================

IDEMPOTENCY (No duplicate visits from same booking)
  ✅ findOrCreateVisitFromBooking() method is idempotent
  ✅ Calling twice with same booking returns same visit
  ✅ Unique constraint on (appointment_uuid, patient_uuid, visit_date)

CONCURRENCY (Visit numbers don't collide)
  ✅ Advisory locks on per-day basis
  ✅ Safe for ~100+ simultaneous check-ins per day
  ✅ Tested in SPRINT1_VERIFICATION_CHECKLIST.sql

WALK-INS (No booking required)
  ✅ Design ready (appointment_uuid = NULL)
  ✅ is_walkin flag added to emr_visit
  ✅ UI implementation deferred to Sprint 2

TIMELINE EVENTS (No duplication)
  ✅ Triggers log structural events (CHECK_IN, status, vitals)
  ✅ Service layer logs business events (prescriptions, etc.)
  ✅ No overlap, no duplicates

BMI STORAGE (Calculated correctly)
  ✅ Formula: weight_kg / (height_cm/100)²
  ✅ Verified via audit query in checklist
  ✅ Consistent across all records

STATUS TRANSITIONS (Valid state machine)
  ✅ Only forward transitions allowed (no backward)
  ✅ Enforced via trigger validation
  ✅ UI buttons show only valid next states
